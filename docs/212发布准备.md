## 配置和打包

- jar 默认激活 `test`，连接 `192.168.0.212:3306/eltock` 和正式 CK `111.6.204.34:8123`。
- 本机开发必须显式使用 `--spring.profiles.active=dev`。
- `package.ps1` 默认使用公共配置合并 test 配置生成 Docker 发布包，不再误读本地 dev 地址。
- 根目录 `.env` 的 `APP_SECRET_KEY` 必须沿用 212 已有密钥；打包时保留该值。部署包同时携带 CK 管理配置。
- 在 `.env` 配置正式实例可用的 `CK_MANAGEMENT_USERNAME`、`CK_MANAGEMENT_PASSWORD`，再运行 `./package.ps1`。缺失时打包会报错，不生成缺失账号管理凭据的新包。
- Docker 包不包含 dev/test 的内置连接配置，容器激活 `test` 标记，使用 `docker/application.yml` 和生成的 `.env` 注入实际连接。

## 用户对应

升级启动时为启用且缺少绑定的现有用户补建 CK 身份；已有绑定不自动重置，失败记录在用户管理中重试。
内置平台 admin 绑定 `el-admin`，普通用户绑定 `el_user_<平台用户ID>`。禁用用户不初始化。
平台登录密码与 CK 随机凭据独立，不会通过该初始化逻辑修改平台密码。

当前 212 的 admin ID 为 2，user ID 为 3；保留这套用户时，user 对应 `el_user_3`。
本机 admin/user/user01 ID 分别是 1/4/5，不能直接把本机绑定记录复制到正式实例。
迁移本机业务数据还需要一起处理用户 ID、资源归属、CK 实例、物理表及上传文件，不能只导入 MySQL 就认定迁移完成。
