# SFTP 目录 CSV 解析与升级

## 当前实现：Commons CSV 与编码配置（2026-11-16）

### 使用方式与范围

- 同步任务的 SFTP 采集设置新增 **CSV 编码**，默认自动识别，可选择 UTF-8、GB18030、GBK、UTF-16LE、UTF-16BE。
- SFTP 目录结构检测、单文件 CSV/TXT 预览、普通目录导入和新轮次目录续传使用 `ModernCsvTable`；逻辑记录由 Apache Commons CSV 1.10.0 流式解析。依赖接口参考 [Commons CSV 官方源码](https://github.com/apache/commons-csv/tree/rel/commons-csv-1.10.0)。
- 单文件预览直接读远端流，只取请求的记录，不再下载整份 CSV 或扫描完整行数。只有实际读到结尾时返回总数，否则页面不展示虚假的总行数。JSON/Excel 预览仍沿用原路径。
- 本次针对此前报错的 **SFTP 目录 CSV** 链路；本地上传归一化和旧单文件快照链路保持兼容，没有把所有 DuckDB 文件查询替换成新解析器。
- 目录预览返回每个文件的实际编码及分隔符；页面显示编码摘要和具体失败文件。单文件预览可切换编码、表头及尾列策略，从任务入口打开时带入任务配置。

### 识别与错误处理

- 优先识别 UTF-8 / UTF-16 BOM；无 BOM 时先严格检查前 256 KiB 是否符合 UTF-8，否则尝试 GB18030。无 BOM 且含零字节的文件要求明确选择 UTF-16 字节序，不猜测。
- 自动识别是前缀探测，不保证任意文件编码都能无歧义判断。纯 ASCII 前缀而后续才出现非 UTF-8 中文时，需要手动选择实际编码。预览通过不代表全文件通过。
- 探测边界落在多字节字符中间不会误判；正式读取始终严格解码。中途遇到不合法字节会报编码错误，不切换编码、不用问号替换、不丢弃坏行。
- 分隔符沿用数据源的显式设置；未配置时，在有界前缀内用同一解析库比较首条记录的逗号/TAB/分号/竖线候选。未闭合引号、缺列、额外非空列严格模式分别报错。
- 多行短信、带引号逗号、双写引号、前导零和字段空白均保持原文。默认尾列投影和超宽行首空占位修复保留；等宽行的开头空值不会删除；全空逻辑记录跳过。
- 错误带文件、实际编码、已解析记录数及物理行附近位置。缓冲预读可能提前发现后续字节错误，因此不把解码失败断言成表头列数错误。记录读取有内存上限，防止未闭合引号吞入整份大文件。
- SFTP 文件变化报错补充前后大小、修改时间（epoch 秒），便于区分内容增长和仅时间变化；不会绕过源文件版本保护。

### 持久化、断点与发布

- 编码选择保存在现有 `schema_json` v5 中，不新增 MySQL 列。新目录轮次使用 `csvReader=commons-csv-v3`，在 `state_json.upper` 中冻结编码选择与尾列策略。
- 每个文件首次读取表头后、输出业务记录前，保存实际编码和分隔符。恢复只使用这些确定值，不重新自动识别。缺少必要字段或策略改变时停止，避免待确认批次的内容或行位置变化。
- 原 v1/v2 未完成轮次继续原 UTF-8 解析规则；更早无标记的断点继续原 DuckDB 规则。**升级后直接“继续传输”不会把旧失败轮次自动转换为新解析器。**旧轮次完成后下一轮自动使用新解析器。
- 如必须对旧失败轮次切换编码/解析器，应先保存新配置，再明确选择“重新传输”。当前该操作会清空任务目标表并从头重建全部数据，并非只重下一个文件；不能把它当作无损修复按钮。
- 已登记完成且大小/时间不变的文件仍跳过，修改编码不会自动重灌这些文件。
- 前后端一起发布。写入 v5 配置或 v3 断点后，旧后端不能识别这些格式，不可直接降级或手动删版本字段。ClickHouse 目标字段不变。

### 验证

- Java 8 编译、前端类型检查和生产构建；未新增测试类。
- 内存脚本直接调用实际编译类，40 项检查覆盖 UTF-8/GB18030/GBK、BOM、手动 UTF-16、探测边界、错误编码、跨行短信、引号与逗号、不同分隔符、等宽空首列、尾列规则、空记录、缺列、超长未闭合记录、无表头、配置往返保存、旧窗口兼容和新文件编码冻结。
- 未使用用户原始整文件，未连接生产 SFTP/MySQL/ClickHouse，也未部署到 212。不能把样例通过等同于所有远端文件都能导入。

## 历史实现：v1/v2 修复记录

以下为本次改造之前的记录；涉及“新轮次”“本次修复”的描述以以上当前实现为准。

目录 CSV 的预览、普通目录导入和新轮次断点导入统一使用 `CsvTable` 读取逻辑记录。
有表头时，列数及顺序由表头确定；无表头时由第一条数据记录确定。后面的数据不会再通过
DuckDB 样本推断把 7 列扩成 9 列或 11 列。DuckDB 仍用于规范化预览样本的字段类型推断。

- 支持双引号包裹的逗号、换行及双写双引号，保留字段原值、前导零和空白。
- 显式配置的逗号、制表符等优先使用；未配置时根据首条记录在逗号、制表符、分号和竖线中选择。
- 忽略表头末尾无名称的空占位，默认只读取有效表头列数以内的数据；多出的尾列不入库，即使非空。
  有名称的字段即使整列为空，也不会被删除。无表头时用首条记录列数确定结构。
- 新读取器 v2 会识别数据行开头的连续空占位列：例如表头为 7 列，数据行为 `,,,,1,2,3,4,5,6,7,13`，
  删除开头 4 个空列后取 `1,2,3,4,5,6,7`，末尾 `13` 继续忽略。仅当删除开头空列后仍有完整表头列数时才这样处理；
  普通行首字段为空但列数恰好等于表头时不会误删，删除后不足表头列数则明确报错。
- 可关闭“忽略额外尾列”恢复严格校验，额外非空单元格会报错。两种模式下缺列、未闭合引号都报错，
  显示记录号及物理起止行号，不自动拼接正文或跳过坏行。
- 错误定位现已改为准确的物理起止行（支持 LF、CRLF、CR），同时显示实际分隔符。
  原来的“物理行附近”采用读取后的行号，可能指向下一条正常记录。
  额外非空列只展示 UTF-16 长度及前 8 个字符码点，用于识别 BOM、不换行空格或 NUL 等隐藏内容，
  不复制整条业务正文到错误日志。逻辑记录号包含表头，不等于物理行号或目标表写入行数。
- 单条记录上限为 16 Mi 字符，避免损坏的引号把整个大文件读进内存。自动分隔符探测最多读取首条记录的 256 Ki 字符。
- 预览最多读取 100 条完整逻辑记录，约 1 Mi 字符后在记录边界结束；不会在引号内换行处截断。
  同步按现有批次流式读取，不额外生成整文件转换副本。

## 断点与已完成文件

新轮次在原有 MySQL 断点 `state_json.upper` 文件清单中保存 `csvReader=header-records-v2`。
无需修改元数据库表结构，也不新增 ClickHouse 目标字段。

已有 `header-records-v1` 的未完成轮次继续使用 v1 规则，避免已确认批次在升级后改变；
该轮次结束后的下一次执行使用 v2。缺少读取器标记的更旧轮次继续使用 DuckDB 原读取器。

如果旧版本已经把某文件“成功”导入但值全部为空，该文件会因路径、大小和修改时间一致而被跳过。
部署 v2 后应对受影响任务使用“重新传输”，并按页面提示清空或重建目标表；不要删除任务后重建。
结构不匹配被排除的文件不记为已完成，因此部署新版本后正常点击“执行”会再次处理这些文件。
若文件在写入过程中遇到实际坏记录，已确认批次保留，文件不会登记为完成；不能把修改后的源文件直接套用旧断点。

## 非空尾列（例如第 11 列为 `13`）

任务编辑的 SFTP 采集设置提供 **忽略额外尾列**，按用户要求改为**默认开启**。
开启后仍完整解析 CSV，只保留文件定义的前 N 列：有表头时 N 来自有效表头，无表头时 N 来自首条记录。
文件结构仍须与任务选定结构一致。超过 N 的值（包括 `13`、空格等非空值）不入库，整条记录照常按原映射写入。
这个选项不能修复前 N 列内部因缺引号造成的错位；只有确认额外尾列不需要入库、前 N 列顺序正确时才开启。
缺列、未闭合引号等错误仍然停止读取。

新建任务、未携带此参数的预览请求以及历史数组格式的旧任务，默认开启。已显式保存 v2 `false` 的任务保持关闭。
部署新版后，当前仍使用历史数组配置的失败任务可直接点击普通“执行”；显式关闭过的任务需先开启并保存。
不需要修改原文件，也不要为了开启此选项重建映射。
`header-records-v2` 在开启“忽略额外尾列”时还会移除数据行开头的连续空占位列。该规则
不改变逻辑记录边界；尾部策略仍不纳入配置指纹，但会核对文件摘要和未确认批次摘要。
如果整行只有与表头相同数量的空列，或删除开头空列后不足表头列数，任务会明确报错，不会把全空行当成成功数据写入目标表。
v1 未完成批次继续按原规则输出，避免升级后重读已确认行时发生错位。其他配置变化仍按原断点保护规则处理。

开关保存在 MySQL `el_sync_tasks.schema_json`：读取历史列数组时按默认开启处理；保存时始终使用
`{"version":2,"columns":[...],"ignoreExtraCsvColumns":true}` 或显式 `false`，确保关闭后重启不会又开启。
外部 API 的 `schema` 仍为列数组。
本轮执行策略也写入现有断点文件清单，手动执行、自动重试和定时触发读取同一份任务配置。
目录检测和预览默认使用 v2 行首空列修复；普通导入、手动执行、自动重试和定时触发均读取同一任务配置。
执行结果会说明已启用忽略额外尾列。
无需执行 DDL，不新增 ClickHouse 字段。旧版程序不能读取 v2 任务配置；如需回退应使用升级前备份，
不能靠关闭开关回退格式，也不要用旧程序续传已经采用新策略写入的未完成轮次。
