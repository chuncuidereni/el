# 一体化与离线交付

部署支持两种模式，默认仍为 `external`。独立模式包含程序、ClickHouse 25.3.14.14 和 MySQL 8.0.46，固定补丁版本，不使用 latest。

| 模式 | MySQL / ClickHouse | 数据 |
| --- | --- | --- |
| external | 使用原 `.env` 和 application-test.yml 的外部地址、账号 | 沿用当前数据库及 app-data 卷 |
| standalone | 自动启动 mysql、clickhouse 容器，使用容器网络名称连接 | 独立 MySQL、CK、程序数据卷，全新平台 |

切换模式不迁移已有账号、任务、断点或 CK 数据，也不会因外部连接失败自动创建空库替代生产库。源数据仍需要自行配置；独立部署消除的是平台对外部 MySQL、CK 服务的依赖。

## 打包

在项目根目录执行：

```powershell
# 现有外部数据库模式，保持原命令兼容
.\package.ps1

# 独立部署，服务器联网构建程序并获取固定版本数据库镜像
.\package.ps1 -Mode standalone

# 推荐的完整离线交付：本机构建程序并打包三个 Linux amd64 镜像
.\package.ps1 -Mode standalone -Offline

# 同一个离线交付包也可以默认连接外部数据库
.\package.ps1 -Mode external -Offline
```

也可在本机根目录 `.env` 设置 `DEPLOYMENT_MODE=standalone`，然后执行 `.\package.ps1 -Offline`。默认 external；命令行 `-Mode` 优先。独立模式不要求配置任何外部数据库，也不读取外部数据库配置来生成连接参数。

离线打包机需要 Python 3.12+、PyYAML 和运行 Linux 容器的 Docker，首次打包需要联网获取镜像及编译依赖。产物仍是 `release/el-to-ck-212.tar.gz` 和对应 `.sha256`，镜像直接包含在同一个 tar.gz 中。会生成较大的文件，请预留约 10 GB 以上可用空间；以后可复用构建缓存。

数据库和平台加密密钥首次生成后保存在本机私有文件 `.env.standalone`，以后打包复用，不会每次随机更换。该文件不会进入镜像或 Git；配置值仅进入交付包私有 `.env`。请与数据库备份一起保留原始密钥文件。不得删除后重新生成来升级已有独立数据库。

独立模式初始平台账号为 `admin`，初始密码为私有 `.env.standalone` 中的 `BUNDLED_ADMIN_PASSWORD`（如之前通过 external 打包生成，则复用当时可用的管理员密码）。无需手动填写数据库密码。平台已有账号后，重新部署不会重置登录密码。

## 服务器执行

目标为 Linux x86_64，预装 Docker Engine 和支持 `up --wait` 的 Compose v2；离线包不包含操作系统或 Docker 安装器。不要求宿主机安装 Java、Node、Maven、MySQL、ClickHouse 或 Python。建议至少 4 核、8 GB 内存，磁盘按实际数据量配置。

手动复制两个发布文件到 `/home/wuhaiyang/upload`，在服务器执行：

```bash
bash <<'DEPLOY'
set -euo pipefail
umask 077
cd /home/wuhaiyang/upload
sha256sum -c el-to-ck-212.tar.gz.sha256
mkdir -p /home/wuhaiyang/el2ck-releases
release_dir="$(mktemp -d /home/wuhaiyang/el2ck-releases/release-XXXXXX)"
tar -xzf el-to-ck-212.tar.gz -C "$release_dir"
cd "$release_dir"
bash deploy.sh up
curl --fail --silent --show-error --max-time 15 \
  "http://127.0.0.1:17878/assets/release-info.json?t=$(date +%s)" -o .served-release.json
cmp web/public/assets/release-info.json .served-release.json
echo "部署完成，后续管理目录：$release_dir"
DEPLOY
```

访问 `http://服务器IP:17878`。离线包自动执行 docker load 并核对镜像 ID，服务器不执行构建或拉取镜像；源码包仍会构建。两种包都先校验文件，再等待数据库健康、执行元数据结构及 CK 连接预检查，最后切换应用。

同一个包临时选择另一模式可使用 `DEPLOYMENT_MODE=standalone bash deploy.sh up` 或 `DEPLOYMENT_MODE=external bash deploy.sh up`。这只是本次调用的覆盖，后续命令也应指定同一模式；日常交付建议直接在打包时固定模式。独立模式生成的包不包含外部数据库配置，若要改成 external，需要按现有配置重新打 external 包。

## 初始化、升级和数据持久化

MySQL 仅在**全新空数据卷**执行包内 V1–V11 及后续 progress 字段初始化脚本，全部成功后才写初始化完成标记。已有数据卷不会重新执行历史 DDL；初始化中途失败会保持不健康，排查修复前不要删除有业务数据的卷。外部数据库模式完全不执行这套初始化。

应用仍执行只读结构校验。今后新增表字段，既有独立数据库与外部数据库一样需要执行对应的升级 SQL；初始化脚本不替代已有库升级方案。

独立模式分别持久化 MySQL `/var/lib/mysql`、CK `/var/lib/clickhouse`、CK 日志、程序 `/app/data`。默认项目名固定为 el-to-ck，新发布目录会复用这些命名卷。程序卷保存上传文件和续传快照，因此备份不能只有 MySQL。

独立数据库不发布 3306、8123、9000 宿主机端口，只对程序所在 Docker 网络开放。数据库容器的健康检查和应用的预检查都通过后，才认为部署成功。

`bash deploy.sh stop` 只停止应用，保留数据库服务；rollback 回退应用镜像和旧配置，不回退数据库内容。不要使用 `docker compose down -v`，也不要清理正在使用的数据卷。切换部署模式会使用另一套应用数据卷；外部 CK/MySQL 的数据不会自动复制过来。

官方镜像初始化与账户配置参考：[MySQL 官方镜像](https://hub.docker.com/_/mysql/)、[ClickHouse 官方镜像](https://hub.docker.com/r/clickhouse/clickhouse-server/)。
