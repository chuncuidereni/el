## 2026-10-30：断点锁清理与查询删除

### 后端会话锁

同步目标表断点和 ARB 工作流断点原先在 `RELEASE_LOCK` 失败后只调用 `Connection.close()`。使用 Hikari 连接池时，这通常只是归还连接，仍存活的数据库会话可能继续持锁。ARB 获取锁的响应丢失时还会因为本地未标记成功而跳过释放；同步断点指纹不匹配则会走两次关闭。

- 增加 `MysqlNamedLock`，由任务执行锁、同步目标表锁和 ARB 工作流锁共同使用。释放失败先调用 JDBC `abort` 终止物理会话，再归还连接；清理错误记录日志并保留原业务异常。
- 初始化失败或获取锁响应丢失时也执行释放，避免实际已获取的锁遗留。`GET_LOCK` 只有明确返回 `0` 才视为被占用，`NULL`、缺失结果及驱动错误作为数据库故障上报。
- 断点 Session 的关闭保持幂等，关闭后拒绝检查/写入；移除指纹不匹配时多余的关闭。获取、检查和释放锁均设置查询超时。
- 不更改锁名、任务分段策略、断点格式或 MySQL 表结构。本轮无新增 SQL 需要执行，也没有操作真实同步任务。

### 查询删除

批量删除原先用“所有勾选 ID”判断是否退出编辑器，部分失败时可能关闭实际未删除的查询并丢失当前编辑状态；确认阶段尚未设置忙碌标记，也可能重复提交。

- 单条和批量删除从确认阶段开始防重入，同一记录不会同时被两条删除流程提交。批量请求固定使用确认时的记录快照。
- 只在服务端确认删除成功时关闭对应编辑器，并统一取消自动保存、延后执行及旧响应。删除失败的查询继续保留编辑内容。
- 批量使用静默请求，最后汇总具体失败名称和原因；刷新后保留失败项勾选。列表刷新失败也会移除已确认删除的行，避免再次操作已不存在的记录。
- 关闭页面后不再继续提交剩余删除请求或操作页面状态。
