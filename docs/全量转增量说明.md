# 已完成全量任务切换增量

适用于先导入历史数据，再持续同步新增数据的任务。升级应用后，原任务不需要删除，也不需要清空目标表。

## 操作

1. 确认原全量运行已经成功完成。
2. 编辑同一任务，把策略改为“增量”，选择已映射的递增字段，例如自增 ID；保留来源、目标、字段映射、批次大小和分段配置。
3. 保存后点击“执行”。第一次执行会核验全量断点、目标表身份及已写入行数，再从全量结果建立增量起点。
4. 后续可以手动执行或使用原有定时调度。两者调用同一同步引擎，均使用已持久化水位；失败后“继续传输”沿用该轮断点。

不要为这次切换选择“重新传输”：该操作的语义仍是重新开始，可能清空目标重建。

如果已把任务改成增量，并遇到“增量配置已改变，不能沿用旧水位”，升级后可直接再次执行。前提是原全量断点仍存在，且没有同时修改来源、目标或映射等配置。

## 新建增量任务连接已有目标表

这与“修改原全量任务”不同。断点按任务 ID 保存；新建任务不会自动继承其他任务的断点。删除任务也会删除该任务的断点，因此重新创建同名任务不能恢复原来的全量证明。

遇到“目标已有数据但没有可信增量断点”时，应先确认目标数据来自哪个任务、是否完整写入，以及原任务和断点是否仍保留。不能仅凭目标最大 ID 自动认定更小 ID 的所有数据都完整。

如果旧全量任务已经删除，但确认目标数据已完整导入，可使用新任务的 **接管已有全量数据**：

1. 确保当前任务已停止；可先停用定时调度。新任务保持原数据源、原目标表和原字段映射，模式选增量，增量字段选递增 ID。
2. 在任务操作菜单或失败任务下方点击“接管已有全量数据”。
3. 查看目标表、数据源标识、现有行数和精确水位。确认该水位及之前的历史数据完整后，点击“确认历史数据完整并接管”。
4. 页面提示起点已保存后，启用任务并点击“执行/继续传输”，或等待定时调度。此后均从保存的水位继续。

接管只写入新任务的 MySQL 断点，不清空目标表、不重写历史数据、不伪造历史运行成功记录。存量行数与本任务新增写入行数分开记录。旧版“仅采集完快照、尚未写入”的失败任务可以接管；已经开始写入、存在未确认批次、已有有效起点或配置不匹配的任务会拒绝覆盖。

预览和确认会分别核对目标来源、类型精度、非空水位及续传列，并使用任务锁和目标锁防止与同步并发。预览凭证绑定当前用户、任务配置、断点版本、表身份、行数和水位，15 分钟有效；这些信息变化后需重新预览。系统不能凭行数和最大 ID 证明历史数据没有缺口，完整性仍需用户确认。

目前接管入口支持 MySQL、PostgreSQL、ClickHouse 表数据源；要求目标是没有依赖视图的普通 MergeTree，且全部行的来源标识与当前数据源一致。不会为了接管自动补列或改表。

已确认起点的 MySQL/PostgreSQL 快照增量会把水位条件放入源查询，ClickHouse 快照增量也会按水位读取。程序不再每轮把全部历史行传回后过滤；实际查询速度仍取决于源表增量字段的索引或排序键。

接管审计字段与水位均保存在现有 `el_sync_checkpoints.state_json` 中，无需修改表结构。旧失败快照不再复用，由已有自动清理机制回收。

程序现在会在打开源数据、采集快照、验证旧快照缓存之前检查此条件；不满足时直接结束，不再先扫描数千万行。写入前仍会复查，防止采集期间目标表发生变化。

“阶段已处理 N/N 行”只说明当前采集或校验阶段完成。是否写入成功以“已确认写入行数”和运行结果为准，不能把阶段 100% 当作同步成功。

## 水位和数据保留

- 转换前重算旧版本的全量配置指纹，只有确认为已完成全量才允许转换。普通增量任务修改增量列、目标表或映射仍会拒绝沿用旧断点。
- 起点取自已成功写入的目标结果，**不取源表当前最大值**，避免跳过全量完成之后新增的数据。
- 快照任务使用原全量轮次的目标数据计算水位；JDBC 分段任务使用单键或“增量字段、稳定主键”复合游标。
- 原全量目标行数不符、目标被重建或修改、字段存在空值或类型转换可能损失精度时会停止转换，保留原断点供排查。
- 转换后的水位和目标身份继续写入 MySQL 的 `el_sync_checkpoints.state_json`。无需修改 MySQL 表结构，不依赖已清理的快照缓存文件。
- 手动执行、定时执行、失败后继续运行都遵守同一断点规则。

## 字段与读取方式限制

增量同步适合追加数据，不是数据库 CDC。新行必须位于现有水位之后；更新旧记录、删除源记录、回填较小 ID/较早时间不会自动同步。

未配置稳定主键的快照任务按 `增量字段 > 水位` 过滤。时间相同的新记录可能被过滤，建议使用唯一且持续递增的 ID；支持的 JDBC 分段任务使用复合游标处理同水位下更大的主键。复合游标仍不能覆盖晚到且不大于现有游标的数据。

增量字段必须来自原全量映射，且源类型、映射类型、实际目标类型之间都不能损失范围或精度。不能使用经过号码转换或自定义默认值转换的列。

续传写入状态已改为保存在 MySQL，不再要求目标具有 `_el_sync_round`、`_el_sync_row`。切换增量仍须通过原配置指纹、目标身份和已确认行数校验；旧版全量使用旧轮次列核对，新协议按来源及已确认行数核对，无法证明完整性时停止，不猜测水位。
