# 字段去重条件

日期：2026-10-20。

## 使用方式

在“添加条件”中选择字段，将关系改为“字段去重”，无需填写比较值。

适用入口：标准源表及其他表的数据列表、目标表圈选、可视化查询的过滤条件和聚合后过滤、探索向导的过滤步骤。

- 普通条件先筛选，再对结果去重；一个字段保留每种字段值的一条完整记录，多个字段按组合值去重。
- 去重在分页和导出条数限制之前执行，总数统计使用去重后的记录数。
- 有排序时优先保留排序靠前的记录；排序相同时使用行内容作为次级排序，避免在相同数据上反复查询选中不同记录。数据变动后需重新查询。
- 空值参与去重，同一去重键组合中的空值保留一条。
- 嵌套条件组中的“字段去重”统一作用于筛选后的结果，不参与 AND/OR 布尔比较。
- 可视化查询中的去重作用于最终结果。聚合查询先分组和聚合后过滤，再按选定结果字段去重；它不会改变聚合统计前的输入行数。
- 目标表的导出、画像统计和保存数据包沿用最近一次成功查询的条件与排序。画像下钻会保留原有去重规则。
- 字段去重只改变查询结果；原表数据保持不变。

## 实现

沿用现有条件 JSON，新增操作符 `op: "distinct"`，不需要数据库迁移。已保存的旧条件配置继续有效。

通用表格由 `TableService` 统一生成筛选后的完整行子查询，通过 `ORDER BY ... LIMIT 1 BY ...` 去重，列表、总数、导出、画像和落表共用。新增可选 `orders` 参数传递画像和落表的保留记录顺序，与新建表的物理排序键 `orderBy` 分开。

可视化查询由 `QueryPlanBuilder` 提取 WHERE/HAVING 中的去重字段，与已有 `distinctKeys` 合并并校验字段；隐藏字段使用真实表达式，程序算子列不能下推去重。恢复配置时保留隐藏字段标记。
