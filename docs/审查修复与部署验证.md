## 1. 高优先级问题处理结果

| 原编号 | 修复结果 |
| --- | --- |
| 2.1 元数据结构缺校验 | 增加只读启动校验和独立 `MetadataCheckCommand`，按契约检查 36 张表的所需列。缺表/列时拒绝启动并提示手工 SQL，不执行 DDL，不依赖迁移 checksum 或历史版本记录。 |
| 2.2 同步跨实例重入 | 新增 `SyncExecutionGuard`，在创建 running 记录之前获取任务级 MySQL 会话锁；运行与收尾结束才释放。已有目标表断点锁继续保护批次写入。 |
| 2.3 启动误重置其他实例 | 删除无条件启动重置入口；恢复必须先取得同一任务锁。持锁中的其他实例不会被重置。 |
| 2.4 收尾失败卡住 running | 结构化记录收尾失败；每 30 秒尝试恢复没有执行会话的 running 记录，下一次手动运行也会先恢复。数据库仍不可用时保留状态并报警，不假装成功。 |
| 2.5 ARB WHERE 权限边界 | 受限表达式解析器只接受列、常量、比较/逻辑/算术运算和显式白名单函数，拒绝子查询、UNION、表函数、字典函数、UDF、注释及查询设置；限制长度和递归深度。执行前重新核对源表权限。 |
| 2.6 工作流忙碌状态覆盖 | ARB 和 DWD 页面改用 `Set<number>`，每个工作流独立登记/释放；同一 ID 重复点击拒绝启动。 |
| 2.7 分组成员删除失败被忽略 | 逐条收集失败成员及原因，有失败就保留分组，显示实际成功数；批量删除也汇总失败详情，避免连续全局弹窗。 |
| 2.8 后台失败没有提示 | ARB/DWD 展示后台终态错误；同步终态失败展示后端原因，并保留执行日志入口。 |
| 2.9 永久轮询吞错 | 4xx 终止轮询；网络故障/5xx 有限退避，连续五次失败停止观察。silent 请求遇 401 仍清会话并跳登录，只有登录自身的 `_skipAuth` 豁免。 |
| 2.10 编译签名错误 | 补齐 CK 工作流配置、JDBC 分段读取/索引校验、Kafka 位点进度、Hive 超时重载、运行日志分页接口。完整 Maven 编译、测试、JAR 打包通过。 |

MySQL 会话锁的释放语义依据 [MySQL 官方锁函数说明](https://dev.mysql.com/doc/refman/8.0/en/locking-functions.html)。本实现适用于各实例连接同一元数据库 MySQL 服务的部署，不应让元数据库代理把这些连接路由到互不共享锁状态的多个写节点。首次从旧版升级必须停旧版任务；旧版程序本身不会遵守新增任务锁。

## 2. 同时处理的问题

- 将断点仓库实际接入手动构造的同步引擎，运行时传入 runId 和执行锁校验。任务 DTO/保存逻辑补齐批次大小、超时、分段键和断点展示信息。
- 保持所有任务自动续传的原行为，移除强制续传后不可达的普通进度分支。分段键为空继续使用快照路径；SFTP 无需数据库主键。
- 收尾保留已上报的进度和读写行数，避免最后一次统计为零覆盖已有进度。
- 取消只表示请求已提交，线程仍登记到真正退出；服务关闭先中断工作线程并等待有限时间。
- CK 建连、校验失败和正常关闭均主动清理 TLS 隧道；JDBC close 失败也不会跳过隧道关闭。
- ARB 后台线程发生 Error 时仍尝试写失败状态并释放工作槽。进度单独写 `progress` 列，兼容读取旧 SQL 中已有的进度文本。
- 日志请求增加异常捕获，抽屉更新使用请求序号和任务 ID 校验；终态立即刷新历史，重新运行前读取最新任务与断点状态。
- Docker 健康检查改用 `/api/health?deep=true` 检查元数据 MySQL；响应不再公开驱动错误。它不代表每个用户的 ClickHouse/外部源都可用。
- 增加容器内存上限，默认 4 GiB，保留 2 GiB Java 堆以外的空间；默认元数据连接池增至 20，为长持有的任务/断点锁留出余量。
- 发布包附带文件 SHA-256 清单；`deploy.sh` 自动验证，再检查卷写权限和 MySQL 结构，通过后才替换现有容器。
- 部署前记录旧的健康镜像 ID，提供 `rollback`。同镜像重启、失败发布重试不会覆盖已记录的旧镜像。

## 3. 验证记录

- Maven `verify`：64 个测试，0 失败、0 错误，生成可执行 JAR。
- 前端：36 个测试文件，477 个用例全部通过；`npm run typecheck` 和 `npm run build` 通过。
- 新增回归覆盖：WHERE 越权表达式、结构契约缺表/缺列、执行锁占用/失效/释放异常、日志分页参数、TLS 监听清理、4xx/网络失败、并发摊平、分组/批量删除部分失败。
- 原前端四个失败中：历史刷新及旧响应保护已修复；“分段键必须填写”和英文耗时字符串的断言已改为符合现有快照续传契约和中文展示的断言。
- Compose 配置、Bash 语法、Python AST、Mapper XML 均完成静态校验。独立预检入口用无效 JDBC 协议验证会明确失败退出，没有启动业务应用或连接数据库。
- 未在本机启动 MySQL/ClickHouse，也未验证 212 的镜像构建、真实任务恢复、数据库权限或健康状态。单元测试中的锁状态使用测试替身，不能替代部署环境的并发联调。
