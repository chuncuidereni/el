# 登录权限与数据隔离设计

> 2026-10-20 更新：CK 身份、表隔离和共享展示以 [CK真实用户与表级权限开发方案](CK真实用户与表级权限开发方案.md) 为准。用户已明确采用共用业务库、精确表级授权、原列表增加“创建者”，不采用个人独立库或独立共享菜单。本文保留为早期设计记录，不代表当前实现状态。

状态：设计稿，尚未实施。本文按用户确认的“用户只能看到自己的数据源和表，或查看其他用户共享的数据”制定。

## 1. 目标与默认规则

采用“平台登录 + 用户所有权 + 指定用户只读共享”。首期不引入租户、部门、项目空间或自定义角色编辑器。

- 新建数据源、表、同步任务、工作流、保存的查询默认私有，owner_user_id 由服务端当前身份写入。
- 用户列表仅展示“我的”和“共享给我的”；创建时间、更新者与所有权分别记录。
- 所有者可以管理自己的资源，并给指定平台用户授权或撤销授权。
- 接收共享的用户只能查看，不可修改、删除、执行写入、修改连接配置或再次共享。
- 查看包括授权范围内的结构、注释、受限分页数据预览；批量导出、同步、工作流使用不包含在查看中。
- 平台管理员负责账号和平台运维。普通业务接口不因为管理员身份而自动放行其他用户的业务数据。
- 如确需管理员接管资源，使用独立、明确授权的管理操作，记录原因和审计；不设置隐式绕过。
- 账号禁用或离职不直接删除其表与任务；由管理员按流程暂停任务、移交资源。

## 2. 现状与改造依据

| 现有位置 | 已确认的行为 | 改造方向 |
| --- | --- | --- |
| web/src/api/http.ts | sessionStorage 保存 Base64 用户名和密码，每次请求带 Basic 头 | 改为服务器会话，浏览器不保留密码 |
| BasicAuthFilter / AuthController | 逐请求验证密码；登录只返回 username、role，无服务器登出 | 标准认证、会话失效和登录生命周期 |
| AuthContext | ThreadLocal 仅存 username、role | 身份使用不可变 userId，补充 sessionId；授权按资源查询 |
| RoleAuthFilter | admin/user + 路径黑名单，普通用户可访问共享业务 API | 功能权限与资源授权分层，未声明业务访问默认拒绝 |
| AppUserService | 已有创建、改密、重置密码方法；未发现接通的平台用户管理 Controller | 补全接口、页面和状态校验 |
| MetadataRepository / ArbWorkflowRepository | 存在全量列表和仅按 id 的访问 | 列表、详情、修改、执行等统一加入授权范围 |
| QueryService | 使用连接配置及请求 allowWrite 判断写入；支持 SQL 和导出 | 不能把连接可见性、allowWrite 当作表级授权 |
| ConnectionService / DataSourceStatusService | 有连接配置缓存、全局数据源状态缓存 | 命中缓存仍先鉴权，状态输出按可见资源过滤 |
| ScheduledSyncRunner 等 | 存在线程池和后台运行路径 | 任务保存运行身份并在执行时重新鉴权 |

元数据已存在 MySQL 建表脚本 src/main/resources/db/mysql/V1__metadata.sql；仓库混用 MyBatis 与 JdbcTemplate。不能只增加 MyBatis 拦截器就认定全部 SQL 已隔离。

## 3. 授权模型

请求通过条件：账号有效且会话有效，具备该功能权限，且为资源所有者或持有有效共享授权。

### 3.1 资源和权限

| 资源 | 所有者 | 共享接收者 |
| --- | --- | --- |
| 数据源 | 查看、编辑配置、测试、删除、管理共享 | 查看安全摘要，以及明确共享表的结构和预览 |
| 注册表 | 查看、预览、允许的管理操作、共享 | 结构与受限预览 |
| 同步任务/工作流 | 查看、编辑、运行、删除 | 首期不共享 |
| 保存的查询、运行记录、日志、上传文件 | 所有者访问 | 首期不共享；表共享不自动开放这些内容 |
| 数据导出 | 所有者且具备导出功能权限 | 首期不包含，后续单独授权 |

建议权限标识：datasource:view、datasource:manage、table:view、table:manage、resource:share、query:execute、data:export、sync:run、workflow:run、user:manage。

资源所有权只决定资源范围，不意味着普通用户获得平台管理、任意 DDL 或数据库超级权限。

### 3.2 数据源共享与表共享

为避免“共享一个数据源就把所有新表也暴露出去”，首期采用显式表清单：

1. 所有者点击数据源“共享”，选择接收用户，再勾选允许查看的表。
2. 后端一次事务写入数据源摘要查看权限及所选表的查看授权；未勾选的表不可枚举、预览或查询。
3. 新增表默认私有，不自动进入旧共享范围。
4. 单独共享一张表时，对方获得该表的展示与预览入口，以及展示所必需的脱敏来源名称；不授予父数据源的配置权限。
5. 不返回账号、密码、密钥、解密配置、SFTP 真实路径和不必要的主机详情；接收方仅能按资源 ID 请求服务端代理预览。
6. 撤销数据源共享时，界面列出本次将撤销的表权限，按共享记录精确撤销，避免遗留访问。
7. 不支持接收方再次共享、公开链接或匿名访问。

“只读查看”不等于防复制；受限预览减少批量读取，但不能保证已显示的数据不会被接收方保存。

## 4. 元数据表设计

复用现有 el_app_users，不复用 ClickHouse 用户管理页面中的用户实体。

### 4.1 登录与账号

- el_app_users 增加 status、must_change_password、password_changed_at、auth_version、last_login_at；密码采用带算法标识的编码。
- 服务端会话记录 user_id、created_at、last_seen_at、expires_at、revoked_at、auth_version；采用框架会话存储，不自己实现令牌加密协议。
- el_audit_logs：actor_user_id、action、resource_type、resource_id、target_user_id、result、request_id、created_at；不存密码、完整凭据或查询结果。

### 4.2 资源所有权

对数据源、同步任务、各类工作流、保存的 SQL、分组、文件等增加 owner_user_id、created_by、updated_by。

物理表当前主要通过连接和库表名定位，应新增统一的表资产目录 el_data_assets：

| 字段 | 用途 |
| --- | --- |
| id | 平台表资产稳定 ID |
| owner_user_id | 所有者 |
| backend_type | clickhouse / source_table / file_table 等 |
| connection_id / datasource_id | 所在后端资源 |
| database_name / schema_name / table_name | 服务端解析出的实际位置 |
| origin_type / origin_id | 同步任务、工作流或导入来源 |
| status | active / missing / deleted |
| created_at / updated_at | 生命周期 |

按后端规范化的物理位置建立唯一约束，保证一张物理表不能被多个用户通过“注册”重复认领。表名变化要更新目录并同步授权；删表后重建必须新建资产 ID，不继承旧表共享。

数据库连接视为平台配置或用户私有资源；平台提供的共享基础设施连接，只表示可使用受控执行通道，不能直接开放该连接下全部库表。

### 4.3 共享记录

el_resource_grants：id、resource_type、resource_id、grantee_user_id、permission、granted_by、expires_at（可空）、created_at。

- 唯一键：(resource_type, resource_id, grantee_user_id, permission)。
- 首期只授予 view，后续扩展 export/use 必须单独定义语义。
- 服务端校验资源存在、授权者为所有者、接收用户有效；不能由客户端伪造 owner/granted_by。
- 多态资源外键无法直接统一约束，应由服务层事务维护授权及资源删除清理。
- 资源查询索引包括 owner_user_id；共享查询索引包括 grantee_user_id、resource_type、resource_id。
- 业务名称唯一性按实际语义调整为所有者范围，物理库表位置仍全局唯一。

## 5. 后端执行链

请求 → 会话认证 → 功能权限 → 资源授权 → 数据访问 → 审计。

增加 ResourceAuthorizationService，提供 requireView、requireManage、requireShare、requireUse；对应 owner/grant 校验集中实现。

- 列表在数据库查询中使用 owner_user_id 或有效授权 EXISTS 条件，分页、总数、搜索、首页统计同时过滤。
- 单资源读写也按资源 ID 和授权范围获取，不能先做列表过滤再认为详情已安全。
- 修改、删除只允许所有者；写操作条件包含 owner_user_id，检查受影响行数。
- 对不可见资源统一返回 404；资源可见但操作无权返回 403；未登录返回 401。
- 批量接口逐个校验 ID，首期任一资源无权则整批拒绝且不产生副作用。
- 校验任务引用的数据源、连接、表以及目标表，防止把别人的 ID 填进自己的任务。
- 表共享不隐式授权关联的源表、物化视图、工作流定义和运行 SQL。
- 文件上传生成服务端文件 ID，目录按用户隔离；预览和下载重新鉴权，拒绝客户端传任意磁盘路径。
- SFTP 目录和文件预览必须使用授权资产及受控路径，不能开放任意路径浏览。
- 连接缓存可以复用底层配置，但每次获取前都要鉴权；查询结果和计数缓存包含有效访问身份及权限版本。
- 不把可变权限永久塞进 session；撤销授权后下一请求应失效，权限缓存同步失效。

## 6. ClickHouse 与外部数据源的真实隔离

仅过滤 MySQL 元数据不够。用户仍可能通过 SQL、导出、全限定表名、元数据枚举或外部表函数访问其他数据。

建议采用“个人数据命名空间 + 数据库原生权限 + 平台表授权”：

- 新生成数据按稳定用户 ID 分库，例如 u_42_ods、u_42_dwd，库名由服务端生成；界面可继续显示贴源层、目标层。
- 平台表目录决定展示范围，ClickHouse 有效查询身份决定数据库实际允许的访问范围。
- 用户交互查询使用受限身份；同步/建表服务身份与查询身份分开。不得用共享超级账号执行用户输入 SQL。
- 共享单表时，对接收者的数据库身份只授予该表所需 SELECT；不授予整个库的通配权限。
- 禁止接收者获得 GRANT OPTION，以及无业务需要的外部访问、任意文件/网络表函数和敏感系统表权限；具体授权结合服务器版本验证。
- 非 ClickHouse 源数据预览首期只开放后端生成的指定表查询，不开放任意 SQL。数据库账号同时按可行范围最小授权。
- 自由 SQL 如果暂时无法落地有效身份隔离，则对普通用户关闭该入口，保留受控表预览。SQL 字符串检测或自动拼 WHERE 不能作为安全边界。
- 首期共享表仅用于预览，不用于用户工作流或同步，避免生成私有副本后绕过撤销。后续增加 use 权限时，必须补充数据血缘及衍生结果访问规则。

共享/撤销涉及元数据与 ClickHouse 两个存储，不能声称同一数据库事务解决：共享先记录 pending、配置数据库权限，成功才 active；失败保持不可访问。撤销先拒绝平台访问并失效缓存，再撤销数据库权限，失败进入可重试队列。平台数据库凭据不交给用户直连。

对进行中的导出/查询，记录执行身份和资源依赖；撤销或禁用后阻止新请求，对可取消的活动查询执行取消。已经返回的数据不能收回。

现有默认 ods_data/dwd_data 和工作流源库默认值需要改成基于资产目录解析，不能只修改页面上的库名。

## 7. 后台任务与共享撤销

- 任务持久化 owner_user_id、运行服务身份及所用资源 ID；执行记录保存 triggered_by 和授权检查结果。
- 手动任务以当前用户鉴权，调度任务按持久化任务所有者/明确的服务主体鉴权。
- 执行前重新检查账号状态、任务归属、源表和目标表权限。任务被禁用、所有者被停用则拒绝新执行。
- 不能依赖请求 ThreadLocal 自动传给线程池，也不能在缺少身份时默认按管理员运行。
- 任务移交必须核验新所有者拥有全部依赖资源权限，不能仅改任务 owner。
- 运行日志、任务进度、错误消息、执行历史均跟随任务归属过滤，清理凭据等敏感内容。

## 8. 登录功能补全

采用 Spring Security + 服务端 Session；当前项目是 Java 8 / Spring Boot 2.7.18，实施时使用与现有依赖兼容的配置方式，不直接套用新版文档示例。框架升级另行评估。

1. 登录成功建立服务器会话并更换会话 ID；生产 HTTPS Cookie 配置 HttpOnly、Secure、SameSite，并配套 CSRF 防护。
2. 登录页只保留用户名记忆选项，不缓存密码；删除旧 sessionStorage 凭据读写逻辑。
3. POST /api/logout 失效服务器会话、清 Cookie；前端清缓存、停止轮询、取消未完成请求，再回登录页。
4. GET /api/me 返回 userId、username、platformRole、功能权限及 mustChangePassword，不返回密码字段。
5. 用户改密校验旧密码；管理员重置后强制首次改密，撤销旧会话。
6. 禁用账号、修改敏感权限后立即撤销相关会话；保护最后一个有效平台管理员，避免全部管理员被删除/降权/禁用。
7. 增加会话空闲及绝对有效期、登录限速和失败退避；失败提示统一，避免账号枚举。阈值作为可配置项。
8. 新密码使用 BCrypt 等自适应哈希；旧盐 + SHA-256 只用于迁移校验，旧用户登录成功后升级哈希，不要求批量恢复明文密码。
9. 用户管理补充创建、禁用/启用、重置密码；个人中心补充改密、最近登录和退出所有设备。
10. 首期采用管理员建号，不开放自助注册；忘记密码由管理员重置。SSO/MFA 可后续增加。

单实例可先使用框架服务器会话；多实例部署前配置共享会话存储及统一撤销机制，不让每台机器保留独立登录状态。

## 9. 前端交互与建议接口

- 数据源和表列表增加“我的 / 共享给我的”，共享资源显示所有者和“只读”标识。
- 所有者操作菜单提供“共享管理”，弹窗选择接收用户及表清单，显示已共享用户、到期时间和撤销按钮。
- 首期用户选择器仅返回必要的 ID、显示名/用户名，不返回全量个人信息。
- 接收者只展示结构、预览入口；共享、编辑、删除、导出及运行按钮按后端 capabilities 隐藏。
- capabilities 仅用于界面展示，每次实际操作仍在服务端验证。
- 平台账号管理与现有 ClickHouse 用户管理保持独立，避免用户误改数据库账号。

接口建议：

| 接口 | 用途 |
| --- | --- |
| POST /api/login；POST /api/logout；GET /api/me | 登录、登出、恢复身份 |
| PUT /api/me/password；POST /api/me/logout-all | 改密、撤销全部会话 |
| /api/app-users | 平台账号管理 |
| GET /api/datasources?scope=mine/shared | 数据源列表 |
| GET /api/data-assets?scope=mine/shared | 表资产列表 |
| POST /api/data-assets/{id}/preview | 按受控资产预览，不接收任意库表路径 |
| GET/POST/DELETE /api/data-assets/{id}/shares[/{userId}] | 表共享管理 |
| POST /api/datasources/{id}/shares | 提交接收用户及显式表 ID 清单 |

## 10. 迁移与实施顺序

第一阶段：账号、会话和所有权基础。

- 备份元数据；以新增版本迁移建立字段和表，不只修改已执行过的 V1 脚本。
- 由部署管理员明确现有资源的所有者；未知归属进入待认领清单，不根据谁首次访问自动归属。
- 盘点现有物理表、任务及其依赖，生成资产目录；历史共享库表在迁移完成前仅向明确授权的所有者开放。
- 用户管理、改密、禁用、登出与统一身份接入；新增资源立即写入 owner。

第二阶段：完整私有隔离。

- 全部列表、详情、写入、导出、预览、统计和后台任务接入授权，补齐混合持久层查询。
- 实现表资产目录和受控预览；按用户配置数据库访问身份。未完成的旁路默认关闭。
- 验证 A/B 两用户不能互相枚举、读取或修改资源，再启用多用户业务使用。

第三阶段：只读共享。

- 实现授权记录、共享管理 UI、数据库授权同步、撤销与审计。
- 验证指定表共享、新增表不继承共享、撤销立即阻断新请求。

第四阶段（可选）：导出授权、工作流使用共享数据、角色定制、SSO/MFA。

历史物理数据移动采用单独迁移计划：校验行数/结构/依赖、调整物化视图、记录映射、切换并保留回退窗口。未验证前不直接改名或搬迁生产表。回滚不得重新开放无权限过滤的旧业务入口。

## 11. 验收用例

- A、B 各建数据源/表：列表、搜索、统计只看到各自资源。
- B 猜测 A 的 ID、连接 ID、库表名访问详情、预览、SQL、下载、导出、运行历史，均被拒绝。
- A 共享表 T 给 B：B 可看 T 的结构与预览；不能看同库其他表、配置密码或任务日志。
- B 不能删除、改名、执行写 SQL、再次共享 T；构造请求绕过按钮同样失败。
- 新增表默认不共享；共享表删除后以同名重建也不继承授权。
- 共享撤销、账号禁用、所有权移交后，缓存、分页计数、活动会话和后续任务行为符合设计。
- 以 B 的实际 ClickHouse 查询身份尝试访问 A 未共享表、system 敏感表和外部表函数，数据库层同样拒绝。
- 同一线程池连续执行 A/B 任务不会串身份；无身份任务不自动获得管理员权限。
- 登出、超时、改密、重置密码后旧会话无法继续使用；前端不保存密码。
- 迁移后旧资源无丢失、无自动公开、无重复认领；最后一个有效管理员不可被误删或禁用。
