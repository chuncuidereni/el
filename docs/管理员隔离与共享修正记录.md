# 管理员隔离与共享修正记录

日期：2026-10-20。

> 历史阶段记录：下文的“admin 与普通用户同样隔离”已被后续明确需求替代。当前内置 admin 绑定配置的 `el-admin`，按其原生授权访问两个业务库的表，详见 [el-admin 库表权限修正记录](el-admin库表权限修正记录.md)。下文测试结果只描述当时版本。

## 本次确认的规则

- 平台 admin 可查看、管理平台账号；普通用户不能访问完整账号管理接口。
- admin 与普通用户使用相同的业务数据边界：只看自己的表及已共享给自己的表。角色或用户名为 admin 均不自动获得其他用户的业务权限。
- 全部平台账号使用独立的 CK 业务身份 `el_user_<userId>`。配置的 CK 管理身份只处理账号、授权及受控管理操作。
- 不需要历史资源重新分配，移除“历史数据归属”菜单和页面路由；没有新增共享菜单。
- 用户在原表列表点击“共享”，从账号名下拉框选择接收者，必要时输入账号名搜索。共享后对方在原列表看到表及原创建者，权限为只读。

## 原因与修正

1. 原库列表由可见表反推，空库也被隐藏。现在将配置的业务库目录与表权限分开，`ods_data`、`dwd_data` 即使没有表也能显示。库名可见不代表拥有库级 SELECT/INSERT。
2. 后续代码曾加入内置 admin 绑定公共业务账号、绕过资产归属的例外，与本次确认的隔离规则冲突。已移除资产列表、表详情、共享管理及生命周期操作中的例外。
3. 旧共享 CK 绑定在业务入口被拒绝，用户管理显示“待隔离”。点击“初始化独立账号”后创建独立 CK 用户，只恢复其自有表与有效共享表权限；不修改原公共连接账号的密码或复制其库级通配权限。新身份与授权核对成功才标记 active。
4. CK 用户信息读取权限不足曾被转换为空列表，误导为“暂无用户”。现在返回明确的管理身份权限错误。平台用户管理继续按平台 admin 角色放行。
5. 共享接收者搜索原先要求预先知道至少两个字符的用户名。现在打开即显示启用用户的账号名，排除本人，最多 50 条，可继续搜索。接口只返回用户 ID 和账号名；禁用用户不出现在候选列表。
6. 绑定重试校验绑定属于指定平台用户；禁用账号不能借重试初始化恢复 CK 执行能力。

## 验证结果

现有后端 47 项测试及新增 3 项针对性回归测试通过；前端现有 463 项测试、类型检查和构建通过；共享弹窗新增 2 项回归测试通过。

在独立临时 MariaDB 10.11、ClickHouse 25.3.14.14、JDK 17 应用实例上，使用真实 HTTP 接口验证通过：

- admin 未建立业务绑定时仍可查看两个空业务库、平台用户和 CK 用户信息。
- 模拟旧 admin 共享绑定，业务 SQL 被拒绝；初始化后绑定 `el_user_1`，管理身份凭据保持可用。
- 普通用户能列出共享接收者，但平台账号管理和 CK 用户管理接口返回 403。
- admin 和普通用户分别建表，双方列表互不可见；直接输入对方完整表名执行 SELECT 被 CK 拒绝，越权删除也被拒绝。
- 普通用户共享给 admin 后，admin 列表显示原创建者并可 SELECT；INSERT、转授和删除均失败。
- 撤权后 admin 列表恢复为空，直接 SELECT 被 CK 拒绝。
- 禁用用户后旧会话失效且共享候选列表不再显示该账号；重新启用并登录后保留自己的表权限，仍不能读取 admin 的表。

本次新增的临时测试代码、验证脚本、测试数据目录和专用容器在验证后清理，保留本记录。原有测试文件保留。

## 使用方式与范围

使用新构建的后端 JAR 与 `web/dist`，重启应用后登录。在“平台用户管理”检查 admin 的 CK 状态：如果是“待隔离”，点击“初始化独立账号”；没有绑定则点击“初始化 CK 账号”。初始化失败会显示原因，不会回退到公共账号。

`el_user_4` 创建的表归属于对应的平台用户。平台 admin 只有在获得该用户共享后才可读取；直接连接 ClickHouse 的管理账号属于另一套身份，其能力由 CK 实际授权决定。

本次没有连接或修改 212 数据库，没有重置现有登录密码，也没有替换或重启用户正在运行的开发/部署服务。上述真实数据库验收针对专用临时环境，不代表现有服务器已完成绑定切换。
