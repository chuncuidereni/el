# EL 跨平台一键运行包

## 接收方怎么使用

1. Windows x64 下载 `EL-Setup-版本-windows-amd64.exe`，双击安装，无需手动解压。macOS/Linux 下载匹配系统和 CPU 的 ZIP 并完整解压。
2. Windows 安装结束选择启动，之后双击桌面的“EL 数仓平台”；macOS 双击 `Start.command`；Linux 运行 `bash Start.sh`。
3. 已有可用 Docker 时直接使用；Windows/macOS 的 `bundled` 包缺少 Docker 时直接使用包内官方安装程序，不在目标电脑下载 Docker。Windows 包还内置 Microsoft WSL MSI。
4. 首次安装可能出现系统管理员授权、Docker Desktop 许可确认、WSL 安装或重启提示。完成后再次双击启动；不用填写数据库 IP、端口或密码。
5. 启动器生成本机独立配置，导入包内镜像，初始化 MySQL 和 ClickHouse，再启动程序并打开浏览器。初始账号密码显示在启动器中；以后可通过 `Login` 入口查看初始密码。

Windows 开始菜单提供“停止服务”“运行状态”“查看初始账号”“运行日志”。便携包的 `Stop`、`Status`、`Login`、`Logs` 对应相同操作。关闭启动器不停止后台容器。
平台中修改过登录密码后，以修改后的密码为准，启动器不会重置账号。

## 自动化范围

- 无需预装 Java、Node、Python、MySQL、ClickHouse；程序和数据库镜像已经包含在包内。
- Windows x64 / macOS Intel、Apple Silicon 使用 Docker Desktop。Linux x64/ARM64 使用 Docker Engine + Compose；缺少 Docker 时自动安装暂支持使用 systemd 的 Ubuntu/Debian。其他 Linux 发行版在已有兼容 Docker 后可运行，暂不承诺自动安装所有发行版。
- Linux 启动器分别在 Ubuntu 22.04（x64）、Ubuntu 24.04（ARM64）构建，需要兼容的 glibc 环境；不支持直接用于 Alpine 等 musl 系统。较旧系统应在对应系统重新构建启动器。
- Windows/macOS 安装程序在**打包时**下载，接收方不再访问 Docker 下载站。Windows 的 WSL MSI 也随包提供；系统组件启用和管理员授权仍需完成，虚拟化必须可用，必要时需要重启。系统组件源文件缺失时会明确失败，不尝试联网补齐 Windows 组件。
- Linux 当前仍通过本机发行版的软件源安装 Docker Engine，需要联网；本次内置安装程序适用于 Windows/macOS，不将 Linux 包标记为离线包。
- Docker Desktop 的许可由用户在其官方界面确认，启动器不代替接受许可。企业适用条件以 [Docker 官方说明](https://docs.docker.com/desktop/setup/install/windows-install/) 为准。
- 默认只开放本机 `http://127.0.0.1:17373`，端口占用时自动选择后续空闲端口。数据库端口不暴露给宿主机。此包默认用于本机独立使用，212 多人访问部署继续用原流程。
- 建议电脑至少有 16 GB 内存和足够磁盘空间，Docker 可用内存至少 8 GB；包内数据库会持续占用磁盘，源文件下载、同步缓存和数据库数据不是零成本。
- 不会携带构建电脑或 212 的 `.env`、账号密码、原数据库或任务数据。每台电脑首次启动随机生成密钥，停止和升级不重新生成。
- 不连接 Docker 的远程 TCP/SSH context，不覆盖已有外部数据库，也不执行 `down -v` 或 Docker 全局清理。

## 配置、数据与升级

配置保存在固定的当前用户目录，与安装文件的位置无关：

| 系统 | 配置目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\ELDataPlatform` |
| macOS | `~/Library/Application Support/ELDataPlatform` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/ELDataPlatform` |

`state.json` 保存密码、项目标识和当前版本；`compose.json` 是自动生成的私有编排配置。不要删除、外传或用其他电脑的文件覆盖。数据库数据放在该项目独立的 Docker 命名卷中，必须和配置一起备份。

重复启动复用当前配置和卷。同一数据库版本/结构的应用升级会复用数据，新应用未就绪时尝试恢复旧应用；回退失败会明确报错，不删除数据。包含数据库版本或初始化 SQL 变化的发行包当前会停止升级，必须补充配套迁移流程后再发版，不能用重新初始化掩盖结构不兼容。

Windows 程序默认安装在 `%LOCALAPPDATA%\Programs\ELDataPlatform`，安装器不要求填写数据库信息。覆盖安装使用同一应用标识和目录，仍读取原 `%LOCALAPPDATA%\ELDataPlatform` 配置；之前用 ZIP 启动过的同一 Windows 用户也沿用该配置。更新前请等待启动器操作完成并关闭启动器窗口。运行中的服务不会因为复制安装文件而被重建，下一次启动平台时才执行已有升级检查。

卸载前从开始菜单选择“停止服务”，然后在 Windows“已安装的应用”中卸载 EL 数仓平台。卸载只删除程序和快捷方式，保留配置、任务、数据库卷、Docker 和 WSL；再次安装后可继续使用。安装器不会自动清理用户数据。

下载文件的 SHA-256 用于检查传输完整性，不等于代码签名。当前启动器未配置 Windows 代码签名和 macOS notarization，系统可能显示未知发布者提示；正式公开发行应接入组织自己的签名证书。不要通过关闭系统安全机制来绕过。

## 开发方怎么打包

原 `package.ps1` / `deploy.sh` 仍服务于 212 私有部署；通用包使用独立入口：

```powershell
cd E:\wenjian\el\el-to-ck-java
.\package-desktop.ps1
```

构建电脑需要 Python 和可用 Docker。此命令在 `release/desktop-build-env` 安装打包依赖，重新构建当前源代码的应用镜像，复用或拉取固定版本数据库镜像，然后在 `release/public/` 生成 Windows 安装 EXE 与 `.exe.sha256`。失败的构建目录保留排查，下一次默认使用新时间戳，不能把残留文件误当成成功包。

Windows 首次打包会从官方发布地址下载固定版本 Inno Setup 7.1.1，验证 Pyrsys B.V. 发布者签名，在 `release/installer-cache` 内以便携模式准备编译工具。接收方无需安装该工具。安装 EXE 内直接包含全部文件，已压缩的镜像和官方安装器不重复压缩，避免打包和安装时浪费时间。编译器来源及安装模式参见 [Inno Setup 官方下载](https://jrsoftware.org/inno-setup/downloads) 和 [官方技术说明](https://jrsoftware.org/inno-setup/documentation/topic_technotes.htm)。

Windows/macOS 的打包阶段还会自动下载官方 Docker Desktop 安装文件；Windows 同时下载 Microsoft 官方 WSL MSI。文件缓存在 `release/installer-cache`，重复打包复用缓存并重新验证发布者签名。包内 `installers/manifest.json` 记录来源、SHA-256 和可读取的安装器版本，`files.json` 校验整个包。下载安装程序失败或签名校验失败时停止打包，不能产出缺失安装器的 `bundled` 包。构建机需安装系统 `curl`；接收方无需安装 Python 或 curl。

Windows 默认只生成 `EL-Setup-版本-windows-amd64.exe`，可直接复制这个文件给接收方。若仍需要便携 ZIP，可给 `distribution/package.py` 添加 `--windows-portable`，同时生成 EXE 和 ZIP。便携 ZIP 需完整解压后运行 `Start.cmd`，保留 `installers` 文件夹。打包与启动都不会代替用户接受 Docker 许可。

完整构建同时保留便携 ZIP 的命令为 `./package-desktop.ps1 -PortableZip`；平时只需 `./package-desktop.ps1`。

仅更新启动器、安装器或说明文档时，可以复用已构建的镜像载荷：

```powershell
.\release\desktop-build-env\Scripts\python.exe distribution/package.py --payload release/payload-已有版本-amd64
```

应用源码发生变化时仍应执行 `package-desktop.ps1` 重建镜像。包体积会随 Docker/WSL 安装器增大；Windows WSL 离线安装方式参见 [Microsoft 官方说明](https://learn.microsoft.com/en-us/windows/wsl/install#offline-install)。

在各系统原生构建启动器时可直接使用：

```bash
python -m pip install -r distribution/requirements-build.txt
python distribution/build_images.py --arch amd64 --version local-20261116 --output release/payload-amd64
python distribution/package.py --payload release/payload-amd64 --output release/public
```

ARM64 改为 `--arch arm64`，启动器必须在对应系统和 CPU 上构建，不能把 Windows EXE 改名当作 Mac 程序。
固定数据库版本：MySQL `8.0.46`、ClickHouse `25.3.14.14`。`runtime.json` 记录精确镜像 ID，接收方校验后按 ID 启动，不使用浮动 latest 标签。

## GitHub Actions / Releases

工作流文件为 `.github/workflows/distribution.yml`：

- 手动运行：构建 Linux amd64/arm64 镜像载荷，再在五种系统/架构组合上构建原生启动器，全部校验通过后自动发布 `build-运行ID-尝试次数` Release。标签指向本次实际构建的提交，下载入口显示在工作流 Summary 中。
- 推送 `v*` 标签：全部包构建并校验成功后，自动上传安装包并发布对应版本的 Release，无需手动点击发布。
- 发布任务使用 GitHub 自带的 `GITHUB_TOKEN`，仅该任务申请 `contents: write`。上传阶段暂存为草稿，全部附件上传成功后自动转为正式发布；上传失败不发布残缺版本，重跑可以补齐草稿。已经发布的同名版本不覆盖，重新发版应使用新标签。
- 产物为 Windows amd64 安装 EXE、macOS amd64/arm64 和 Linux amd64/arm64 ZIP，附 SHA-256；每个包包含数据库镜像，体积明显大于源码包。
- Windows CI 实际静默安装、校验、覆盖安装再卸载；静默安装不自动启动平台。Linux 还检查空数据库初始化、停止及复用数据再次启动。不会在 Windows/macOS runner 上安装 Docker Desktop、自动接受许可或模拟真实用户首次安装。
- 本地 `origin` 是内网 Gitea，`github` 远程指向 `https://github.com/chuncuidereni/el.git`。必须将工作流、`distribution/` 构建文件和所需应用源码提交到 GitHub，GitHub 才能使用这些修改；本地生成 EXE 不会自动更新远程工作流。

### 在 GitHub 上打包并下载 EXE

1. 将最新代码提交到 GitHub。首次添加手动工作流时，默认分支也需要包含该工作流。
2. 打开仓库 **Actions → Build installers (Windows EXE / macOS / Linux) → Run workflow**，选择需要构建的分支。
3. 全部构建和校验完成后，安装包自动发布到**当前 GitHub 仓库**的 Releases；打开最后的 `publish-release` 任务 Summary 即可看到链接。
4. 在 Release 的附件中直接下载 `EL-Setup-*.exe`，复制到 Windows 电脑后双击安装，不需要解压，也无需再手工发布 Release。其他用户按仓库原有访问权限下载。

当前工作流使用 `actions/upload-artifact@v4` 暂存构建产物；从 Actions 的 Artifacts 区下载会得到 ZIP 容器，里面才是 EXE。需要直接获得安装 EXE 时，应从 **Releases 附件**下载，不要选择自动生成的 `Source code (zip)`。参见 [GitHub 产物下载说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts) 和 [Release 创建命令](https://cli.github.com/manual/gh_release_create)。

官方参考：[Docker Windows 安装](https://docs.docker.com/desktop/setup/install/windows-install/)、[Docker macOS 安装](https://docs.docker.com/desktop/setup/install/mac-install/)、[Ubuntu Docker 安装](https://docs.docker.com/engine/install/ubuntu/)、[GitHub 构建矩阵](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/run-job-variations)。
