# el-to-ck Java 项目介绍

## 一、项目概述

el-to-ck Java 是一个以 ClickHouse 为目标数据库的数据同步与处理平台。项目将数据源配置、字段映射、同步任务、库表管理、SQL 查询和多源数据整合集中在一个 Web 系统中，支持从不同来源读取数据，转换后写入 ClickHouse，再进行查询、关联和聚合处理。

项目采用 Java / Spring Boot 后端与 Vue 前端，使用 MySQL 保存平台配置和任务记录，使用 DuckDB 处理本地文件。它是原 Go 平台的 Java 实现，当前功能由 Java 后端和配套前端共同提供。

主要数据流如下：

```text
本地文件 / SFTP / MySQL / PostgreSQL / MongoDB
                        ↓
               数据源配置与结构识别
                        ↓
               字段映射与类型转换
                        ↓
                 全量或增量同步
                        ↓
                    ClickHouse
                        ↓
          库表浏览 / SQL 查询 / 多源仲裁
```

## 二、功能模块

### 1. 登录与权限模块

登录与权限模块负责用户身份认证、登录状态恢复和功能访问控制。

平台区分管理员和普通用户，前端通过路由和页面控制可见功能，后端根据用户角色和接口规则判断操作权限。管理员可以使用连接管理、用户管理、系统监控等管理功能，普通用户可在授权范围内使用数据源、同步、查询等业务功能。

平台登录账号与 ClickHouse 数据库账号分别管理：前者用于访问本系统，后者用于连接目标数据库。

### 2. 目标连接管理模块

目标连接管理模块用于维护平台访问 ClickHouse 所需的连接信息，包括连接名称、主机、端口、数据库、用户名和密码等。

主要功能包括：

- 新建、编辑和删除目标连接。
- 测试连接是否可用。
- 设置默认连接。
- 查看连接状态。
- 根据连接配置访问数据库、表和相关管理功能。

连接信息由平台统一保存，其他模块通过所选连接访问 ClickHouse。密码以加密形式存储，列表按新增优先展示。

### 3. 数据源管理模块

数据源管理模块负责配置同步任务的输入端，与管理 ClickHouse 目标端的“目标连接管理”相互独立。

当前新增页面提供以下数据源入口：

| 数据源 | 用途 |
| --- | --- |
| 本地 CSV 文件 | 上传并读取本地数据文件 |
| SFTP | 读取远程服务器上的文件 |
| MySQL | 读取关系型数据库中的表数据 |
| PostgreSQL | 读取关系型数据库中的表数据 |
| MongoDB | 读取集合中的文档数据 |

系统中还保留列式数据库和库内表数据源的相关实现，但当前新增页面的这两个入口已置灰禁用。底层文件处理还包含 JSON、XLSX 等能力，与新增页面入口范围有所区别。

主要功能包括数据源分组、配置编辑、通信测试、文件上传、结构预览及字段识别。编辑页面测试连接时使用当前填写的配置；密码留空时可以复用已保存密码。

数据源按主机、类型和用户名进行重复校验，同一组合只允许保存一条连接。端口、业务数据库或分组不同，不改变这一重复判断。新建的数据源显示在列表前部。

**MongoDB 配置**区分业务数据库和认证数据库：业务数据库决定读取哪个库的集合，认证数据库用于验证用户身份。两者可以相同，也可以不同。系统支持普通参数配置和完整连接串，并可识别文档中的嵌套字段。

### 4. 映射同步模块

映射同步模块是项目的核心功能，用于建立来源字段与目标字段的对应关系，并将数据写入 ClickHouse。

任务配置包含数据源、来源对象、目标连接、目标库表、字段映射、字段类型、同步策略及自动建表等信息。页面采用向导形式，将来源选择、字段配置和任务设置分步呈现。

#### 字段映射与校验

系统同时展示源字段类型、映射类型和已有目标表的实际类型，对以下情况提供提示或拦截：

- 字段缺失或映射为空。
- 重复字段映射或重复目标列名。
- 普通映射与自动维护字段冲突。
- 源类型与目标类型不兼容。
- 整数范围、Decimal 精度或时间戳精度不足。

校验不仅存在于前端页面，也会在任务保存和实际执行时进行。依赖具体数据值的转换，在运行过程中继续检查。

MongoDB 嵌套字段可以通过路径映射到目标列；自动生成目标列名时，将点号转换为下划线，并对重名进行区分。

#### 全量与增量同步

| 策略 | 处理方式 |
| --- | --- |
| 全量同步 | 读取来源数据；是否先清空目标表由任务配置决定，未开启清空时直接追加 |
| 增量同步 | 根据配置的增量字段和目标端水位，读取满足增量条件的数据 |

数据按批次读取、转换并直接写入目标表。增量字段支持数值、日期和时间戳，处理过程中保留相应的范围与精度。

当前实现不创建 `_el_sync_batch`、`_el_sync_seq` 或 `_el_sync_…` 暂存表，也不使用这套批次恢复机制。任务失败时，之前已经成功写入的数据可能保留，后续执行仍按任务的全量或增量策略处理。

#### 默认字段与运行记录

系统保留来源和写入时间等默认字段。常规模式使用 `source_id`、`create_time`，ODS 模式使用 `ods_source_id`、`ods_insert_at`，SFTP 目录任务还使用 `path` 标识来源文件。实际字段组合由任务模式决定。

任务执行生成独立运行记录，保存运行状态、读取行数、写入行数和错误信息。前端按本次运行 ID 跟踪状态，运行中的任务不能修改或删除。

### 5. SFTP 文件同步模块

SFTP 文件同步用于处理远程目录中的文件，支持目录、文件匹配规则和文件结构配置。

系统通过文件路径、大小和修改时间识别文件变化，对已同步且未变化的文件进行跳过，对新增或变化文件执行读取和写入。文件结构与选定结构不一致时，会排除该文件并记录提示。

同路径文件重灌前按 `path` 删除对应旧数据，写入成功后更新文件同步记录。强制全量重建会清空目标数据与文件去重记录，再处理目录中的文件。

### 6. 库表工作台与数据分层模块

库表工作台提供 ClickHouse 数据库和表的统一访问入口；贴源层与明细层页面以不同业务视角组织库表和数据。

主要功能包括：

- 浏览数据库、表和分组。
- 查看字段结构、建表 SQL、主键、排序键和分区键。
- 分页预览表数据。
- 按条件过滤、排序和选择列。
- 导出查询或表数据。
- 在相应页面进行表结构、数据及相关表级操作。

表预览与导出共享部分字段、过滤和排序规则。对于 ClickHouse 驱动不能直接识别的聚合结果类型，系统会在读取时进行兼容转换。

平台配置保存在 MySQL 中，实际业务表和数据保存在 ClickHouse 中，两者分别承担管理信息和业务数据的存储职责。

### 7. SQL 查询与查询工作流模块

SQL 查询模块提供 SQL 编辑、执行、结果展示、保存查询和查询分组等功能。

查询页面同时包含可视化查询能力，通过选择数据源、字段及关联条件生成查询计划。查询工作流负责管理相关配置与执行过程，支持项目内已有的数据处理管线。

主要能力包括：

- 编辑和执行 SQL。
- 保存查询配置并按分组管理。
- 查看分页结果和导出数据。
- 使用可视化方式组织查询。
- 执行包含字段处理规则的查询计划。

普通 SQL 执行与可视化查询工作流使用不同的处理路径，分别负责直接 SQL 执行和查询计划生成、字段处理等逻辑。

### 8. 多源仲裁工作流模块

当前“工作流”页面对应多源仲裁功能，用于将多个来源中同一对象的信息按字段规则进行整合。

系统根据配置生成聚合层、每个来源对应的物化视图以及服务层，支持仲裁、求和、取最大值、取最小值等字段规则。

主要操作包括：

| 操作 | 功能 |
| --- | --- |
| 配置与计划 | 定义来源、字段规则并生成处理计划 |
| 生成 | 创建相关对象并回填历史数据 |
| 重建 | 重新计算聚合层 |
| 服务层处理 | 将聚合结果整理为服务层数据 |
| 现状查询 | 查看表、视图等对象状态 |
| 运行历史 | 查看执行结果与错误信息 |

配置记录与 ClickHouse 产物分别管理，删除工作流配置与删除数据库产物是不同操作。

服务查询对部分 min/max 聚合结果显式转换为普通字段类型，以适配日期、时间和数值列的读取。部分服务层处理由后台周期任务执行。

### 9. 调度与任务执行模块

调度模块负责按任务配置触发执行，并管理运行状态与结果记录。

项目支持内部定时调度和可选的 XXL-JOB 执行器模式，默认关闭 XXL-JOB，采用内部调度。手动执行与定时执行共同使用相应业务执行逻辑。

服务启动时会处理旧进程遗留的运行中状态，使其体现为已中断。运行状态处理与业务数据写入相互独立，不表示已经写入的数据被自动回滚。

后端还保留通用 DAG 工作流及旧 JOIN 型宽表相关能力。当前前端工作流入口使用多源仲裁页面，旧宽表路由被注释，未作为当前菜单的独立开放入口。

### 10. 首页、系统监控与工具模块

首页汇总平台相关业务信息，为连接、任务及其他功能提供概览入口。

系统监控页面展示本机和相关目标端的运行信息。工具模块提供哈希计算、加解密和 DDL 体检等功能，字典页面提供对应的页面内容。

| 功能 | 页面 |
| --- | --- |
| 首页 | `/home` |
| 系统监控 | `/system` |
| 哈希工具 | `/tools/hash` |
| 加解密工具 | `/tools/crypto` |
| DDL 体检 | `/tools/ddl-check` |
| 字典 | `/dict` |

监控和工具访问受平台角色权限控制。

## 三、技术架构

### 1. 前端

前端使用 Vue 3、TypeScript、Vite 和 Element Plus，结合 Pinia 管理状态、Vue Router 管理页面路由。SQL 编辑等功能使用 CodeMirror，可视化相关页面使用对应图形组件。

前端按页面、公共组件、接口封装和工具函数组织，业务页面通过统一 API 封装访问后端。

### 2. 后端

后端使用 Spring Boot 2.7.18，按接口、业务服务、数据访问和执行引擎分层组织。

| 层次 | 职责 |
| --- | --- |
| Controller | 接收 HTTP 请求并返回统一响应 |
| Service | 业务校验、配置管理与流程协调 |
| Repository / Mapper | 平台元数据访问与数据库迁移 |
| Sync | 数据读取、转换、增量处理和同步写入 |
| Arb / Workflow | 仲裁与查询计划生成、执行 |
| CkPool / Duck | ClickHouse 访问和文件数据处理 |
| Config / Util | 认证权限、初始化、类型、SQL、文件和加密工具 |

### 3. 数据存储与外部访问

| 组件 | 作用 |
| --- | --- |
| MySQL | 保存连接、数据源、任务、用户、分组、运行记录和文件同步记账 |
| ClickHouse | 保存目标业务数据、聚合表、服务层及视图 |
| DuckDB | 文件结构探测、查询与读取 |
| JDBC 驱动 | 访问 MySQL、PostgreSQL、ClickHouse 等数据库 |
| MongoDB Driver | 读取文档集合和执行源端条件查询 |
| JSch | 建立 SFTP 会话并读取远程文件 |

连接密码等敏感配置通过项目加密工具处理后保存。外部业务数据与平台管理数据分别存储。

## 四、项目结构

```text
el-to-ck-java/
├─ src/main/java/com/el2ck/
│  ├─ controller/      接口层（按业务模块分包）
│  ├─ service/         业务服务（按业务模块分包）
│  ├─ mapper/          MyBatis 接口（按业务模块分包）
│  ├─ entity/          实体与请求响应模型（按业务模块分包）
│  ├─ repository/      JDBC 仓储与 metadata 基础设施
│  ├─ sync/            同步执行
│  ├─ arb/             多源仲裁
│  ├─ workflow/        查询工作流
│  ├─ ckpool/          ClickHouse 访问
│  ├─ duck/            文件处理
│  ├─ job/             调度任务
│  ├─ config/          配置、认证与初始化
│  └─ util/            公共工具
├─ src/main/resources/ 后端配置、迁移脚本与按模块分目录的 Mapper XML
├─ web/src/            前端页面、组件和接口封装
├─ data/               实例运行数据
└─ docs/               项目说明文档
```

模块目录与命名说明见 [README](../README.md)。后端测试包已移除，构建使用 `mvn clean package`。

## 五、运行形态

项目可以采用前后端分别启动的开发方式，也可以由后端直接提供前端构建产物。

开发模式中，Vite 前端默认使用 17373 端口，将 `/api` 请求代理到 17878 端口的 Java 服务。部署模式中，后端默认从 `web/dist` 提供前端页面。

后端构建产物为 `el-to-ck-server.jar`，上传、缓存和本地文件默认位于 `data/`，平台元数据保存在独立的 MySQL 数据库中。任务配置和运行记录由 MySQL 管理，ClickHouse 与其他外部数据源作为独立服务被平台访问。

平台元数据库默认连接 `192.168.0.212:3306/eltock`，平台表统一使用 `el_` 前缀，启动时通过版本化脚本初始化。数据库口令通过外部配置或环境变量提供。
